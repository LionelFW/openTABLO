# openTABLO

A mobile take on RATP's TABLO: next departures, traffic info and Vélib' availability around you,
wherever you are in Île-de-France. Runs on the web (desktop and mobile) and as a native Android/iOS app.

```
backend/   .NET 9 API (ASP.NET Core minimal APIs, EF Core, PostgreSQL + PostGIS)
frontend/  Vite + TypeScript web app, wrapped with Capacitor for Android/iOS
```

## How data is fetched

| Data | Source | Cost | Strategy |
|---|---|---|---|
| Stops, lines, line colours | IDFM open data exports | free | Imported into PostGIS, refreshed daily by a background service |
| Vélib' stations | Vélib' GBFS | free | Imported daily; live availability cached 60 s |
| Address search | IGN Géoplateforme | free | Proxied by the API so users' queries do not leave from their device |
| Next departures | PRIM `stop-monitoring` | **quota** | One call per stop area, cached 45 s, shared by all users |
| Traffic info | PRIM `disruptions_bulk` | **quota** | One bulk call for the whole region, cached 5 min |

PRIM calls go through `PrimQuota`, which books slots in PostgreSQL: the daily budget (default 900 of
the 1000 allowed) and the per-second cap (default 4 of 5) hold across every API instance and restarts.
The app loads departures automatically for the 3 nearest stops only; others load on tap.
`GET /api/usage` shows today's consumption.

## Privacy

- Location is only requested when the user taps "Utiliser ma position"; an address field is always available instead.
- Coordinates are rounded to ~11 m before leaving the device, used for one query, and never stored or logged.
- Only the chosen radius is kept (in local storage).

## Development

Requirements: .NET 9 SDK, Node 22+, Podman or Docker.

```bash
# 1. Database (PostGIS)
podman run -d --name opentablo-db -p 127.0.0.1:5432:5432 \
  -e POSTGRES_USER=opentablo -e POSTGRES_PASSWORD=opentablo-dev -e POSTGRES_DB=opentablo \
  -v opentablo-pgdata:/var/lib/postgresql/data docker.io/postgis/postgis:17-3.5

# 2. PRIM key, stored outside the repo (run in your own terminal)
cd backend/OpenTablo.Api && dotnet user-secrets set PRIM_API_KEY "<your key>"

# 3. API on http://localhost:5183 (applies migrations, imports referentials on first start)
dotnet run

# 4. Web app on http://localhost:5173 (proxies /api to the API)
cd frontend && npm install && npm run dev
```

Tests: `cd backend && dotnet test`.

Schema changes: `cd backend/OpenTablo.Api && dotnet ef migrations add <Name> -o Data/Migrations`.

## Native apps

Native builds call the deployed API, so set its URL at build time:

```bash
cd frontend
VITE_API_BASE=https://opentablo.example.com npm run build
npx cap sync
npx cap open android   # Android Studio
npx cap open ios       # Xcode (macOS)
```

Location permissions and their explanations are declared in `android/app/src/main/AndroidManifest.xml`
and `ios/App/App/Info.plist`. Add the native origins to `Cors:Origins` if you change them.

## Deployment (Coolify)

1. New resource → your Git repository → build pack **Docker Compose** (`compose.yaml`).
2. Set the environment variable `PRIM_API_KEY` (optionally `PRIM_DAILY_BUDGET`).
   `SERVICE_PASSWORD_POSTGRES` is generated by Coolify.
3. Assign a domain to the `api` service (port 8080). Health check path: `/health`.

The single image serves both the API and the web app. Migrations run at startup
(`Database:MigrateOnStartup`); disable it and apply them from CI if you scale to several replicas.

## Configuration

All settings live in `backend/OpenTablo.Api/appsettings.json` and can be overridden with
environment variables (`Section__Key`), e.g. `Search__MaxRadius=2000`, `Prim__DeparturesCacheSeconds=60`.

## Design

Follows RATP / IDFM signage conventions: navy and jade identity, mode-shaped line pictograms
(circle for Métro, square outline for RER/Train, bars for Tram, rectangle for Bus) using official IDFM
line colours, and large countdown times. RATP's typeface Parisine is proprietary; it is used when
installed and falls back to Helvetica/Arial otherwise.

Data: Île-de-France Mobilités (PRIM, open data), Vélib' Métropole, IGN.
